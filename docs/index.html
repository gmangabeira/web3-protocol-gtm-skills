Web3 Protocol GTM Skills

Three Claude skills that run the Web3 go-to-market diagnostic I use in client work, adapted for self-serve protocols. Evidence-backed findings, not generic advice.

Most Web3 protocols don't have a marketing problem. They have a diagnosis problem.

Why this exists

Channels exist, numbers are moving, and nobody can say which specific thing is holding growth back. These skills walk Claude through a structured diagnostic, narrative, distribution and the post-launch growth system, and force evidence-backed findings.

The method is the self-serve version of the 6-pillar framework behind my Web3 growth audit. Each skill names which pillars it covers.

How it works

Inputs in, scored findings out

Each SKILL.md tells Claude exactly what inputs to collect, how to score what it finds, and what output format to produce. Missing surfaces are findings, not blockers.

The kit

Three skills, one diagnostic

All three are shipped. Every claim gets a status marker, a severity flag and quoted evidence.

narrative-diagnostic

Whether your positioning actually lands. Produces a scored narrative scorecard with severity flags and concrete rewrites.

Workflow

  1. One-sentence test on the homepage hero
  2. ICP clarity
  3. Differentiation: could a competitor paste this claim?
  4. Proof and evidence
  5. Message consistency across site, X bio, pinned post, docs
  6. Jargon test against the ICP

distribution-competitive-scan

How your channels stack up against 2-3 direct competitors. Produces a channel comparison table, an engagement-rate benchmark and three prioritized moves.

Workflow

  1. Channel inventory
  2. Engagement rate benchmark (last 20 X posts)
  3. Content mix read
  4. Owned audience check
  5. System check: connected system or islands

post-tge-growth-system

Why growth stalled after token launch. Separates real growth failure from market beta, maps funnel leaks, and produces a 90-day fix list.

Workflow

  1. Beta check: token vs BTC, TVL vs sector
  2. Funnel walk: discovery to repeat transaction
  3. Activation loop inventory
  4. Attribution stack check
  5. Owned audience check
  6. Synthesis: exactly three ordered fixes

Which skill first?

Start from the symptom

The post-TGE skill starts with a market-beta check, so you don't spend a quarter fixing marketing when the whole sector is down.

Install

Claude Code

Personal skills, available in every project. For a single project, copy the three folders into that repo's .claude/skills/ directory instead.

bash

git clone https://github.com/gmangabeira/web3-protocol-gtm-skills.git
cp -r web3-protocol-gtm-skills/narrative-diagnostic \
      web3-protocol-gtm-skills/distribution-competitive-scan \
      web3-protocol-gtm-skills/post-tge-growth-system \
      ~/.claude/skills/

Any other Claude interface

On claude.ai or the API: open the skill's SKILL.md, paste its contents into your conversation, and add your protocol's details. The skills are plain markdown: no dependencies, no build step.

Use

Just ask

Once installed, just ask. Each skill tells Claude what inputs to collect.

prompts

Run the narrative diagnostic on [protocol]: homepage is [url], X is [@handle]

Compare our distribution against [competitor A] and [competitor B]

We launched [token] 2 months ago and TVL is bleeding. Run the post-TGE growth system audit.

What this kit can't see

Public surfaces and the numbers you bring

The skills run on public surfaces and the data you provide. They do not include:

  • Onchain cohort queries (Dune)
  • Scraped competitor social intelligence
  • SEO and AEO analysis
  • A prioritized 90-day roadmap

Rules every skill follows

  • No invented numbers
  • Every severity flag needs evidence, or an explicit "no data exists", which is itself the finding
  • No "post more consistently" style advice
